## B2 — campaign rotation hold (burst+LRU)  [karpathy_runner]
Problem (measured): selection at the main loop is a pure `last_nudge` LRU
sort, so after each round a repo goes to the BACK of the queue — an open
campaign ("N consecutive rounds sharing one checklist", §6.2) would wait
hours between its own rounds. The Phase A "burst+LRU (K=2, persisted)"
blocker-6 claim referred to machinery that lived in the rotation.json engine
F4 retired (0 refs to "burst" in the tree today).
Design:
- Extract selection into `pick_next_project(projs, reg)` (module-level,
  testable). Key: `(0 if held else 1, last_nudge)` — an open campaign holds
  the rotation; among held repos and among the rest, LRU by last_nudge.
- Held = campaign exists AND state=="open" (BLOCKED campaigns do NOT hold)
  AND `campaign_holds < MAX_CAMPAIGN_HOLDS` (=15, MAX_ROUNDS_PER_CAMPAIGN+3;
  belt-and-braces against a wedged-open campaign monopolizing the loop).
- Persisted counter `entry["campaign_holds"]`, bumped by the main loop when
  the hold selects the repo (rides the registry persist run_round already
  does). Reset to 0 when the campaign CLOSES or goes BLOCKED (commit block).
  Cap release logs loudly and re-enters normal rotation while open.
  SEMANTICS (review a-1, 2026-09-30): the cap is a LIFETIME hold quota for
  this open campaign, NOT a consecutive-streak bound -- a reset-on-
  interruption would let a wedged campaign monopolize in an A-B-A pattern.
  Lifetime is the safer anti-monopolization reading; wording updated.
- Non-campaign rounds keep the locked pure-LRU behavior byte-for-byte
  (flagged default #1 below).
Drill D5: plant the key back to last_nudge-only -> hold test RED.

## B3 — opening gate (LOCAL / CROSS_CUTTING / UNCERTAIN)  [scope + prompt]
Problem: today an opening campaign needs only a CROSS_CUTTING line; "LOCAL"
is implicit and "UNCERTAIN" is inexpressible — an unsure child just omits
the line, which is indistinguishable from LOCAL, so drift can start silently.
Design:
- New marker, asked FIRST in the required-final-lines block (surface in play
  only; legacy callers unchanged):
      SCOPE: LOCAL | CROSS_CUTTING | UNCERTAIN -- <what is unclear>
- `scope.parse` gains `scope_class` (first line wins within a message,
  case-insensitive), `uncertain_note`, `scope_dropped` (extra lines counted,
  never swallowed — T3-4 lesson).
- `scope.propose` gates OPENING and WIDENING on the classification:
  * class CROSS_CUTTING or absent (legacy) + cross line -> opens as today.
  * class LOCAL + cross line -> CONTRADICTION: no open, no widening; recorded
    (`res["contradicted"]`), logged. The checklist's SURFACE-DONE verdicts
    still fold (independent of cross).
  * class UNCERTAIN -> no open, no widening (`res["uncertain"]=True`);
    the runner records `entry["scope_question"]={round,note}`.
- Runner lifecycle: a later LOCAL/CROSS_CUTTING classification SETTLES and
  clears the question; another UNCERTAIN refreshes it. The prompt renders an
  "OPEN SCOPE QUESTION (from round N): settle it this round" block via a new
  `scope_question` build() param.
- loopctl: add READ-ONLY `--show-campaign` (design §6.2 said it; missing) —
  prints per-project campaign summary from threads.json. No flag writes scope.
Drill D6: plant the gate open on LOCAL-contradiction -> RED.

## B4 — closing gate (narrow falsification, repo-cited)  [scope + runner]
Problem: a `done` verdict is pure claim text; "added the field" is neither
narrow nor falsifiable, and the campaign can CLOSE on it (the mechanical
verdict-map-full check is the only gate). §6.2's honest-limits note says a
done "remains a claim" — B4 narrows the claim so the runner can partially
verify it.
Design:
- `scope.default_cite_check(root)` -> predicate(reason)->bool. Extracts
  path-shaped tokens (slash paths + bare filenames) from the reason text and
  verifies ≥1 exists in a bounded one-shot file index of `root`
  (os.walk, skip .git/.venv/node_modules/__pycache__, cap 20k entries,
  basename index for bare names). Predicate raises = fail-closed (uncited).
- `propose(..., cite_ok=None)`: when provided, a `done` verdict whose reason
  carries NO verifiable citation is DOWNGRADED to `done-uncited`
  (non-terminal), the attempt increments, the reason gains the gate note,
  and `res["uncited"]` lists the slug (runner logs loudly). Consequence: an
  uncited claim can never be terminal, so the verdict-map-full close check
  cannot fire on it — the closing gate falls out of the per-round rule.
  Re-emission WITH citations next round takes the existing terminal-upgrade
  path (attempts reset, T2-11 unblock interplay preserved).
- Only `done` is gated. `not-applicable` stays terminal ungated (flagged
  default #2: it is the reasoned exit for "this surface does not need the
  change"; citations do not apply; it is already tracked distinctly for
  audit).
- cite_ok=None -> today's behavior (all existing callers/tests unchanged).
- Runner: passes `cite_ok=scope.default_cite_check(wt)` at the propose site
  (the accepted round's worktree = the tree the claims describe, pre-merge).
Drill D7: plant the downgrade off -> RED.
